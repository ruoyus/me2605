ME2605 / GD CONVERGENCE

How many updates does gradient descent need? The distribution decides.

Eight datasets drawn from different probability distributions, one fixed optimiser, run until the gradient norm reaches 10⁻³ — or one million updates, whichever comes first.

Gradient norm vs updates

Full-batch gradient descent, step size 1/L. The horizontal rule is the 10⁻³ target; the vertical rule is the 10⁶-update cap. The ×3000 run leaves the cap with its gradient still at 0.53.

Loss vs updates

The four stretched-Gaussian runs converge to the same optimal loss 0.0818 as the unscaled blobs: stretching an input coordinate changes only the conditioning, not the answer.

The eight distributions

Each card: a 240-point view of the drawn dataset (stretched sets plotted with the stretch removed), its condition number κ, the resulting step size, and the number of updates to reach ‖∇L‖ ≤ 10⁻³.

Method

Data
400 points per dataset (200 per class), one fixed seed (mulberry32, seed 7), drawn once and never resampled.
Model
Linear least squares: features (1, x, y), target = the ±1 class label, loss L(w) = ‖Φw − t‖²/2n. Strictly convex and quadratic, so the Hessian ΦᵀΦ/n does not move during the run.
Optimiser
Full-batch gradient descent, w ← w − η∇L(w), η = 1/L with L = λ_max(ΦᵀΦ/n) from a power iteration. Per-step decay of each eigendirection is exactly (1 − λᵢ/L).
Stopping
Stop when ‖∇L‖₂ ≤ 10⁻³, or after 10⁶ updates. Recorded points follow a geometric schedule (~1.03× spacing).
Check
Across the three stretching factors the measured updates-to-target divided by κ is 4.03 / 4.16 / 4.27 — the same constant for three decades of κ, the shape the bound r ≥ (κ/2)·ln(1/ε) predicts.
